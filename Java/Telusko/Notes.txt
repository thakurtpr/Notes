[switch-case]
===========================================================================================================================

| Component | Description                                         |
| --------- | --------------------------------------------------- |
| `switch`  | Tests a variable/expression against multiple values |
| `case`    | Defines possible values and associated code blocks  |
| `break`   | Exits the switch block (prevents fall-through)      |
| `default` | Runs if no `case` matches (optional, like `else`)   |


public class SwitchExample {
    public static void main(String[] args) {
        int day = 3;

        switch (day) {
            case 1:
                System.out.println("Monday");
                break;
            case 2:
                System.out.println("Tuesday");
                break;
            case 3:
                System.out.println("Wednesday");
                break;
            default:
                System.out.println("Invalid day");
        }
    }
}

[ METHODS ]
===========================================================================================================================
| Component       | Description                                                             |
| --------------- | ----------------------------------------------------------------------- |
| **Method**      | A block of code that performs a specific task and can be reused         |
| **Syntax**      | `returnType methodName(parameters) { // body }`                         |
| **`void`**      | Used when the method does **not** return a value                        |

public class MethodExample {

    // method without return value
    static void greet() {
        System.out.println("Hello, welcome!");
    }

    // method with return value and parameters
    static int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        greet();  // calling method without return
        int sum = add(5, 3);  // calling method with return
        System.out.println("Sum: " + sum);
    }
}

[ METHOD OVERLOADING ]
===========================================================================================================================

Different parameters with different data type 

| Concept                | Description                                                                       |
| ---------------------- | --------------------------------------------------------------------------------- |
| **Method Overloading** | Defining **multiple methods** with the **same name** but **different parameters** |
| **How it differs**     | Varies by **number**, **type**, or **order** of parameters                        |
| **Return type**        | Can be same or different (but alone can’t distinguish methods)                    |
| **Purpose**            | Increases code **readability** and **reusability**                                |

public class OverloadExample {

    // Method 1: no parameters
    static void display() {
        System.out.println("Display with no parameters");
    }

    // Method 2: one int parameter
    static void display(int a) {
        System.out.println("Display with int: " + a);
    }

    // Method 3: two parameters (int and String)
    static void display(int a, String b) {
        System.out.println("Display with int and String: " + a + ", " + b);
    }

    public static void main(String[] args) {
        display();
        display(10);
        display(5, "Java");
    }
}

OUTPUT ::
Display with no parameters  
Display with int: 10  
Display with int and String: 5, Java

[STACK & HEAP]
===========================================================================================================================
-------------------------
STACK : LAST IN FIRST OUT 
-------------------------
Every method will have its own stack 


HEAP :
Will only contain the variables and function definations 
**** variables which are outside the methods in that class





| Feature          | **Stack**                            | **Heap**                                           |
| ---------------- | ------------------------------------ | -------------------------------------------------- |
| **Memory Use**   | Stores method calls, local variables | Stores objects, instance/class variables           |
| **Access**       | LIFO (Last-In-First-Out)             | Random access                                      |
| **Size**         | Generally smaller                    | Larger                                             |
| **Allocation**   | Automatically managed                | Needs garbage collection                           |
| **Lifetime**     | Exists until method finishes         | Exists until no references remain                  |
| **Thread Scope** | One stack per thread (thread-safe)   | Shared across threads (not thread-safe by default) |
| **Performance**  | Faster (simple access and cleanup)   | Slower (due to GC and dynamic access)              |




public class MemoryExample {
    public static void main(String[] args) {
        int x = 10;              // stored in Stack
        MyObject obj = new MyObject(); // obj reference in Stack, object in Heap
        obj.show();
    }
}

class MyObject {
    int num = 100;              // num is in Heap
    void show() {
        System.out.println("Number: " + num);
    }
}


Stack = fast, local data, auto cleanup
Heap = flexible, shared, garbage-collected

String Buffer VS String Builder ;

| Feature             | StringBuffer                                                        | StringBuilder                                                  |
| ------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------- |
| **Thread Safety**   | **Synchronized** (thread-safe)                                      | **Not synchronized** (not thread-safe)                         |
| **Performance**     | Slower due to synchronization overhead                              | Faster because no synchronization                              |
| **Introduced in**   | Java 1.0                                                            | Java 5 (Java 1.5)                                              |
| **Use case**        | Use when **multiple threads** might access/modify the same instance | Use when **only single thread** accesses/modifies the instance |
| **Methods**         | Same API as StringBuilder                                           | Same API as StringBuffer                                       |
| **Capacity growth** | Same growth strategy (capacity \* 2 + 2)                            | Same growth strategy (capacity \* 2 + 2)                       |
| **Example**         | `StringBuffer sb = new StringBuffer("abc");`                        | `StringBuilder sb = new StringBuilder("abc");`                 |

[this KEYWORD]
===========================================================================================================================

🔹 Uses of this:
Refers to current object: Inside a method or constructor.

Resolve name conflict: Between instance variables and parameters.

Invoke current class methods or constructors.

Pass current object as a parameter.




class Student {
    String name;

    Student(String name) {
        this.name = name; // 'this.name' is instance variable, 'name' is parameter
    }


    void display() {
        System.out.println("Name: " + this.name); // refers to current object
    }
}

public class this_keyword {
    public static void main(String[] args) {
        Student obj  =  new Student("Thakur");
        obj.display();
    }    
}

class Animal {
    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.sound(); // Inherited from Animal
        d.bark();  // Defined in Dog
    }
}

[this and super]

there is a method inside every constructor which isn't visible i.e 
super();


---------------------
:::::Super usages::::
---------------------
Call the parent class constructor
Call the parent class method
Access the parent class field


********
every class in java extends from object class 
********



class Animal {
    String type = "Animal";

    Animal() {
        System.out.println("Animal constructor called");
    }

    void makeSound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    String type = "Dog";

    Dog() {
        super(); // 1. Call parent class constructor
        System.out.println("Dog constructor called");
    }

    void displayType() {
        System.out.println("Type: " + super.type); // 3. Access parent class field
    }

    void makeSound() {
        super.makeSound(); // 2. Call parent class method
        System.out.println("Dog barks");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.displayType();
        d.makeSound();
    }
}

| Usage           | Code                | Explanation                                                  |
| --------------- | ------------------- | ------------------------------------------------------------ |
| **Constructor** | `super();`          | Calls `Animal`'s constructor from `Dog`                      |
| **Field**       | `super.type`        | Accesses `type` from `Animal`, not from `Dog`                |
| **Method**      | `super.makeSound()` | Calls `Animal`'s `makeSound()` before adding custom behavior |

[METHOD OVERRIDING]
===========================================================================================================================
Same name , same parameters with different body 

if class extends from another class having same name and same parameters in both the classes 
it will take the child class method if we create the object of child class which will override the method of class a

| Requirement            | Description                                                          |
| ---------------------- | -------------------------------------------------------------------- |
| Method name            | Must be the same as in the parent class                              |
| Parameters             | Must match exactly (same number, order, and type)                    |
| Return type            | Must be same or subtype (called *covariant return type*)             |
| Access modifier        | Must not be more restrictive than the overridden method              |
| Non-final method       | The method in the superclass must not be `final` or `static`         |
| `@Override` annotation | Recommended but not mandatory (helps catch mistakes at compile time) |



CLASS STRUCTURE:

+---------------------+               +-------------------------+
|     Superclass      |               |        Subclass         |
|---------------------|               |-------------------------|
| + displayInfo()     |  <--------+   | + displayInfo()         |
|   (prints "Super")  |           |   |   (prints "Sub")        |
+---------------------+           |   +-------------------------+
                                  |
        Method Overriding (Same method name, signature, return type)

RUNTIME BEHAVIOR:

SuperClass obj1 = new SuperClass();
obj1.displayInfo();   --> "Super"

SuperClass obj2 = new SubClass();
obj2.displayInfo();   --> "Sub"   <- Overridden method is called at runtime

SubClass obj3 = new SubClass();
obj3.displayInfo();   --> "Sub"

[DYNAMIC METHOD DISPATCH]
===========================================================================================================================

Code example 


class Animal {
    void speak() {
        System.out.println("Animal speaks");
    }
}

class Dog extends Animal {
    void speak() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {
    void speak() {
        System.out.println("Cat meows");
    }
}


Animal a;

a = new Dog();  
a.speak();    // Output: Dog barks

a = new Cat();
a.speak();    // Output: Cat meows





             DYNAMIC METHOD DISPATCH
             

                 +-------------------+
Reference Type ->|     Animal a      |
                 +-------------------+
                          |
                          |       (actual object at runtime)
                          ↓
              +-------------------+         +-------------------+
              |   Dog Object      |         |   Cat Object      |
              +-------------------+         +-------------------+
              | + speak()         |         | + speak()         |
              |   "Dog barks"     |         |   "Cat meows"     |
              +-------------------+         +-------------------+

              [a = new Dog();]  →  a.speak()  →  Dog.barks()
              [a = new Cat();]  →  a.speak()  →  Cat.meows()

Resolution:
-----------
✔ `a` is of type Animal → compiler checks method exists in Animal
✔ Object is Dog or Cat → JVM resolves actual method at **runtime**

[final]
===========================================================================================================================
final - variable ,class , method , class 

final variable --- :: constants :: can't be changed 

final class --- :: prevent any class to extend from the current class 

final methods ---- :: prevents any method from subclass to override the current method 




                FINAL KEYWORD STRUCTURE

               +-------------------------+
               |       Shape (final)     |  ❌ Cannot be extended
               +-------------------------+
               | final double PI = 3.14  |  ✅ Value can't be changed
               |                         |
               | final void displayType()|  ❌ Can't be overridden
               +-------------------------+
                          ↑
                          |
                class Circle extends Shape  ❌ ERROR!
                  (Cannot extend final class)

    Memory Behavior:
    ----------------
    Heap:
      Shape Object:
        ├── PI = 3.14159 (final)  ✅ read-only
        └── Method table:
             displayType() → Bound to Shape at compile time (non-overridable)

    Stack:
      s → reference to Shape object on heap

[UPCASTING AND DOWNCASTING]
===========================================================================================================================





class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}

Animal a = new Dog();  // Upcasting
a.sound();             // Valid
// a.bark();           // ❌ Compile-time error


Animal a = new Dog();       // Upcasting
Dog d = (Dog) a;            // Downcasting
d.bark();                   // ✅ Safe if 'a' really refers to a Dog

Animal a2 = new Animal();
Dog d2 = (Dog) a2;          // ❌ Runtime error (ClassCastException)






[ Animal a = new Dog(); ]
     a
     │
     ▼
  ┌──────────────┐
  │  Dog Object  │
  │--------------│
  │ Animal part  │ ← accessible via 'a'
  │--------------│
  │ Dog part     │ ← not accessible via 'a'
  └──────────────┘
[ Dog d = (Dog) a; ] // Downcasting
     d
     │
     ▼
  ┌──────────────┐
  │  Dog Object  │
  │--------------│
  │ Animal part  │
  │--------------│
  │ Dog part     │ ← accessible via 'd'
  └──────────────┘

[ABSTACT KEYWORD]
===========================================================================================================================
--- Defining a class ABSTACT without defining abstract method do have no issue 
--- but defining a abstract method inside a class needs the class to be abstract .  
--- You cannot create object of abstract class.


abstract class Animal {
    abstract void makeSound(); // abstract method

    void eat() {
        System.out.println("This animal eats food.");
    }
}

class Dog extends Animal {
    @Override
    void makeSound() {
        System.out.println("Bark");
    }
}


               ┌────────────────────────┐
               │     abstract class     │
               │        Animal          │
               ├────────────────────────┤
               │ + eat()                │ ◄── Concrete method
               │ + makeSound() ◄───────┐│ ◄── Abstract method
               └────────────────────────┘
                          ▲
                          │ (extends)
                          │
               ┌────────────────────────┐
               │         class          │
               │         Dog            │
               ├────────────────────────┤
               │ + makeSound()          │ ◄── Overrides abstract method
               └────────────────────────┘


You cannot create an object of an abstract class: Animal a = new Animal(); ❌
Abstract methods act like contracts—subclasses must implement them.
Abstract classes can have both abstract and concrete methods.
A subclass must be marked abstract too if it doesn’t implement all abstract methods.

[INNER CLASS]
===========================================================================================================================
public class Outer {
    private String greeting = "Hello";

    // Inner (non-static) class
    public class Inner {
        public void sayHello() {
            // Can access Outer’s private field
            System.out.println(greeting + " from Inner!");
        }
    }

    public void createInner() {
        Inner inner = new Inner();
        inner.sayHello();
    }
}

// Usage:
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
inner.sayHello();  // prints "Hello from Inner!"



┌──────────────────────────────────┐
│           class Outer           │
│──────────────────────────────────│
│ – private String greeting       │
│                                  │
│ + void createInner()            │
│                                  │
│   ┌──────────────────────────┐   │
│   │      class Inner         │   │
│   │──────────────────────────│   │
│   │ + void sayHello()        │   │
│   │   // uses greeting       │   │
│   └──────────────────────────┘   │
└──────────────────────────────────┘



Outer o = new Outer();
Outer.Inner i = o.new Inner();

[ANONYMOUS CLASS]
===========================================================================================================================
interface Greeting {
    void sayHello();
}

public class Main {
    public static void main(String[] args) {
        Greeting greeting = new Greeting() {
            @Override
            public void sayHello() {
                System.out.println("Hello from Anonymous Class!");
            }
        };

        greeting.sayHello();
    }
}

┌────────────────────────────┐
│       interface Greeting   │
│────────────────────────────│
│ + sayHello()               │
└────────────┬───────────────┘
             │
     implements (ANONYMOUS)
             ▼
┌─────────────────────────────────────────────┐
│    new Greeting() {                         │
│        @Override                            │
│        public void sayHello() {             │
│            System.out.println("Hello");     │
│        }                                     │
│    }                                         │
